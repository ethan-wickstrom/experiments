# This repository

It holds the experiments and projects that the owner builds with coding agents. Each project has its own top-level directory and its own documents. Nobody else works here, and nobody reviews it.

## Projects

| Directory | What it is | Read first |
|---|---|---|
| `frond/` | A research vehicle for coding-agent harnesses: which mechanisms make an agent solve more terminal tasks per dollar on the same model? | `frond/CLAUDE.md` |
| `rachis/` | A typeface family for dense technical reading, generated by a program: Rachis Mono (fixed pitch), Rachis (proportional, with optical sizes) and Rachis Math (for formula typesetters). | `rachis/CLAUDE.md` |

A new project gets a new top-level directory, the documents listed under "What every project keeps", and a row in this table and in `README.md`.

## Autonomy

The agent owns this repository: architecture, scope, priorities, experiments, naming, and merging its own PRs.
- Decide, record the reason in the project's decisions document, and continue. Don't offer the owner options.
- The authority covers this repository only.
- Ask the owner only for what you cannot get yourself: API keys, money, accounts, infrastructure. When you ask, say exactly what you need, what it costs and what it unblocks, and keep working on everything else. An open request is an entry in the project's ledger.

## Starting and resuming

1. Find the project the task belongs to and read its `CLAUDE.md` before anything else. It says what the project is for, where its documents are, what is in flight and which checks to run. A project's `CLAUDE.md` is loaded automatically only once a file in its directory has been read, so read it yourself first.
2. Run `git log --oneline -15 origin/main` for the latest work.
3. A task that belongs to no project starts a new one.

## What every project keeps

In its own directory:
- `README.md`: what the project is and how to run it.
- `CLAUDE.md`: what an agent needs to resume it: its purpose, where its documents are, what is in flight, and its checks.
- A decisions document: every decision, with the alternatives rejected and why. A reversed decision gets a new entry; the old one is marked superseded.
- A ledger: every open item (a deferral, a gap, an idea, a question, a request to the owner) and every closed one with its resolution.

## Rules

These hold for every project. A project's `CLAUDE.md` adds its own.

- Work on a branch, open a PR, run the project's checks, wait for the review bots and verify their findings, then merge it yourself with a merge commit. If no bot can review, a PR that changes only documents merges on its checks, and a PR that changes code is reviewed first by a separate agent that sees only the diff and the repository. (The reasons are D15, D17, D40 and D58 in `frond/docs/decisions.md`, where these rules were first decided.)
- Before a turn ends, everything is committed, pushed and on `origin/main`. The Stop hook (`.claude/hooks/stop_guard.py`) checks.
- Ledger discipline:
  - every deferral, gap, idea or question goes into the project's ledger when it appears;
  - an entry's status changes in the same commit as the change that affects it;
  - entries are closed with a link to their resolution, never deleted;
  - no open item lives only in chat, memory or a task list.
- Every decision goes into the project's decisions document, with the rejected alternatives and why.
