# experiments

Experiments and projects built with coding agents. Each one has its own directory, with a README that says what it is and how to run it.

| Directory | What it is |
|---|---|
| [`cwm/`](cwm/README.md) | A TypeScript code world model: collect execution traces, learn next-state predictions and replay repository edits. |
| [`frond/`](frond/README.md) | A research coding agent built on `dspy.RLM`, and the experiments that measure which harness mechanisms make an agent solve more terminal tasks per dollar. |
| [`rachis/`](rachis/README.md) | A typeface family for dense technical reading: Rachis Mono for code and terminals, Rachis for prose and mathematics, Rachis Math for typeset formulas. It is generated by a program, and the fonts are in `rachis/fonts/`. |
| [`verdict/`](verdict/README.md) | The work of making the truth about an idea arrive sooner: the shortest schedule, a protocol for one afternoon with real people and real stakes, and a scored record of guesses. |

`CLAUDE.md` holds the rules an agent follows in this repository; each project's own `CLAUDE.md` says how to resume that project.

## Effect source reference

[`repos/effect/`](repos/effect/) is a read-only copy of [Effect 4.1.4](https://github.com/Effect-TS/effect/tree/effect%404.1.4). A normal clone includes the source, guide, tests and license; there is no submodule to initialize. This follows the [Effect team's Git subtree workflow](https://effect.website/blog/the-one-weird-git-trick-that-makes-coding-agents-more-effect-ive/). For coding instructions, see [AGENTS.md](AGENTS.md#typescript-and-effect).

When upgrading Effect, choose a published v4+ release that matches the consuming project's package dependency. From a clean branch at the repository root, set `tag` to that release and pull the subtree (do not squash away the subtree commits when merging the PR):

```sh
tag='effect@4.1.4'  # replace with the target release
git subtree pull --prefix=repos/effect https://github.com/Effect-TS/effect.git "refs/tags/$tag" --squash
```

Check the version in [the upstream manifest](repos/effect/packages/effect/package.json), update the release link and tag here, and run the consuming project's checks. Use the registry package at runtime, never a relative path into the subtree.
