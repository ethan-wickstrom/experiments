# A code world model should predict what an intervention will reveal

**Architecture decision:** Keep the TypeScript oracle and its raw-frame baseline. Model **where execution goes** and **what changes there**, conditioned on source and observed history. Do not train it to invent exact hidden state. We implement and test these factors on bounded programs; we do not claim state-of-the-art performance on real repositories.

## Why this is the next problem

[Meta CWM](https://arxiv.org/abs/2510.02387) shows how execution and environment trajectories can contribute to a large code model. Its [debugger](https://github.com/facebookresearch/cwm/blob/7930e0298bf32aae28cc0e35e18a54c772603364/demos/cwmdbg.py#L159-L180) conditions on source and prior frames. Its [guide](https://github.com/facebookresearch/cwm/blob/7930e0298bf32aae28cc0e35e18a54c772603364/PROMPTING_GUIDE.md) distinguishes events, actions and observations. None of that guarantees a detached V8 frame is Markov, or that a model which predicts a return predicted the preceding write.

We [grouped the frozen training traces](bench/observability.ts) by exactly what a hypothetical predictor sees, not by execution ID. Across 576 runs, 2,684 named-function frames had 119 distinct source/site keys. Eleven keys admit different next sites; a deterministic site-only predictor must miss at least 118 transitions in this sample. With the full current frame **every key is a singleton**. Zero observed conflicts then says _nothing_ about sufficiency. The [constructed alias twins](bench/belief/README.md) force a repeated observation and demonstrate the missing information. This is an empirical lower bound on errors for the given inputs and dataset, not an estimate of population error.

## State, action and uncertainty

**Does the program counter transfer?** The [branch experiment](bench/branch/README.md) trains on observed arms and parameter writes, then recombines them on five new branching sources. It completes 14/20 self-fed semantic paths, versus 9/20 for a majority-arm baseline. At returns, 19/20 values are correct but **none** of the 20 exact next V8 locations are. A bare-name return in training did not distinguish a fixed column offset from a position relative to the whole expression. The failure of the raw location model survives the success of the semantic model. The separate straight-line parser does not even accept a source from the earlier eight-family transfer holdout; accuracy within a supported grammar is not coverage.

**Can we design an identifying training input?** For the bounded scalar basis, a [positional probe](bench/composition/fingerprint.md) identifies all four coefficients with one exact store instead of the original six per token. It confidently identifies _false_ polynomials for OR and XOR as well. Use synthesized discriminating inputs to identify in-class parameters; use **independent inputs and programs** to falsify the class.

**A negative result changed this design.** We [froze the scalar model and blinded operator names](bench/composition/regime.md). On integer pairs with disjoint bits, addition is indistinguishable from OR or XOR. Trained there, the model unanimously predicted addition and missed all 14 overlapping-bit stores. Giving both tokens the same extra candidate functions replaced all those errors with abstentions. Before reading any pool labels, maximum disagreement picked (3,5): the candidates predicted 8, 7 and 6. One V8 label per token then identified the right rule on all held-out inputs. This is [query by committee](https://doi.org/10.1145/130385.130417), not a general correctness certificate or a demonstrated win over random querying (three of five pool pairs were equally informative).

Use a tagged observation history **H**: source revision, current stack/source span, visible bindings with exactness masks, event kind, and observed prefix. Distinguish a requested breakpoint, an actual V8 pause, a reversible repository edit, and an executed source operation. These have different effects. An unanswered query is not a guest throw. Never put CDP handles, raw outcome, episode success or held-out arguments into prediction features. Execution stays in the oracle. Static parsing, explicit abstract transitions and learned composition are allowed and identified as such.

Write the predictive distribution as:

```text
p(next_visible | H, action)
  = Σ_z,s,d p(z | H) p(s | z,H,action) p(d | s,z,H,action)
             × 1[project(apply(current,d),s) = next_visible]
```

Here z represents distinctions that matter to _future observations_ (e.g. whether a write propagates), s is the successor event/site, and d is a sparse change. This equation is a proposed factorization, not a claim we observe these latent labels. In the implemented array model, two empirical factors suffice: a distribution over cell deltas given write and index, and a probability of the second array following given setup and past signal. Outcomes that are observationally identical are combined; no-op writes supply no evidence of sharing. This is a **response belief**, not a guarantee of heap identity. In the scalar model, each constructor has a set of rules consistent with observed atomic stores. Ordered children compose only when their candidate values agree.

For a larger learned model, encode lexical binding and control-flow edges alongside source tokens. Use query-local pointers for candidate successor sites plus an unknown/other option, and predict destinations and values of a sparse patch rather than regenerating all locals. A recurrent state must retain the past observations needed to distinguish aliases, exceptions and delayed async effects. For multiple references, represent a latent partition or object slots rather than unconstrained pairwise alias decisions. Equality of detached values alone never establishes identity. Retain an ordinary sequence-model comparator with exactly the same input and budget. This is a **challenger design**, not infrastructure already shipped.

## Training loop and promotion gate

1. **Define the observable.** Choose raw next pause, statement store, or a named intervention/breakpoint in advance. Align by source map and execution order, never by searching for the desired value. Preserve unmapped locations, masks and failed collections. Readout and static sequencing get separate credit.
2. **Split by program lineage and intervention.** Keep alpha-renames, edits, arguments and prefixes with their source family; reserve _combinations_ before looking at labels. Check positive controls for representation, held-out depth/operand regimes for extrapolation, and equal-return/opposite-write pairs for shortcuts. The checkerboard experiments intentionally reuse primitive atoms across splits, not whole programs.
3. **Spend label budget on identification.** Start with isolated atomic transitions and balanced context interventions. Select experiments covering absent contexts or separating hypotheses that still agree on old data. Include collisions, no-op writes and non-identifying observations. Use raw V8 and plain execution to qualify the oracle; train only on accepted observations. Keep a sealed fresh test, not just repeated tuning on a familiar benchmark.
4. **Fit what can be observed.** For labels y with mask M minimize −log Σ p(z,s,d | H,a) over compatible projected outcomes, not a loss against a guessed latent z. For candidate selection use exact membership/consensus; for a neural model add a site pointer and conditional sparse write/value heads. Train on both complete and intentionally masked histories, without scoring unknown fields as correct. Weight by source family and event, not just token count or long loops. Only use auxiliary labels the oracle actually observed.
5. **Roll the model forward.** Start from one observed entry state, predict without access to future pauses, and stop credit at the first discrepancy. Report exact full-store/site transitions, wrong predictions, abstentions, joint-pair success, proper probability scores, and rollout survival by horizon. Include per-family results and seeds. Do not restart from an oracle intermediate frame and call it an entry rollout. Compare against retrieval, persistence, terminal readout, masked history, corrupted semantics and an unfactorized learned model.
6. **Promote only at a common target.** The raw baseline also predicts stack, site, event kind and unknown bindings; these candidates do not. A replacement must first improve fresh **raw nonterminal** predictions and entry rollouts at matched coverage, without compromising oracle fidelity. Favor the simpler model when a table or known static transition suffices. A gain at a supplied breakpoint is valuable on its own; it is not evidence that the model can choose the breakpoint or execute arbitrary TypeScript.

## What came from the literature

- [Predictive representations of state](https://proceedings.neurips.cc/paper_files/paper/2001/hash/1e4d36177d71bbb3558e43af9577d70e-Abstract.html): define state by observable consequences of future actions. This motivated the alias twins, not a claim to reconstruct V8's heap.
- [Synantic](https://doi.org/10.1145/3689724) and [IPA-GNN](https://arxiv.org/abs/2010.12621): learn compositional semantics or track an instruction pointer. The experiments distinguish supplied structure from learned behavior; neither reproduces these systems.
- [Measuring compositional generalization](https://arxiv.org/abs/1912.09713): separate atom coverage from compound coverage. Our factorial split is a controlled analogue, not the CFQ benchmark or its divergence metric.
- [Execution tuning](https://arxiv.org/abs/2503.05703), [Debugging Code World Models](https://arxiv.org/abs/2602.07672) and [Towards a Neural Debugger for Python](https://arxiv.org/abs/2603.09951): motivate explicit state, separating action prediction from state tracking, and intervention-conditioned horizons. Python and synthetic results do not transfer automatically to this TypeScript collector.
- [Interchange interventions](https://proceedings.neurips.cc/paper_files/paper/2021/hash/4f5c422f4d49a5a807eda27434231040-Abstract.html): changing a causal input is a stronger test than decoding its correlation. Our signal swap is an **input** intervention; it does not identify a neural circuit.
