# Selected function experiment

The host selects one file and one named exported function in each of two fresh TypeScript libraries. Each starts with a stub return value. A follow-up extends the same function on the resulting project even when the initial edit fails. Each turn adds its visible Bun test. The model sees the path, export signature, current body, visible tests and user requests so far. It gets one greedy prediction of at most 96 new tokens. The requested output is one raw TypeScript return expression. Surrounding whitespace is permitted. Statements, fences, commentary and truncated completions receive no edit or retry. The host changes only the selected return argument and supplies no reference expression.

Use the official Q8 MiniCPM5-1B release and llama.cpp b6602, four CPU threads, a single slot and a context of 16,384 tokens with the stock no-thinking chat template. Run unchanged A, coding-only B and joint C separately with the same prompts and limits. Preserve their raw predictions, visible test output and cumulative independent grades. A solved turn requires an accepted edit, passing visible tests and every hidden suite through that turn passing in a fresh container. Record hidden-only grades separately. Execute the visible and hidden suites on the unchanged state too when the reply is invalid or incomplete. Four turns per arm measure this specific edit operation.
